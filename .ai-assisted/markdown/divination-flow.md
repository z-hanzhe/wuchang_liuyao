# 起卦到结果

## 首页与请求

- `feature/home/` 提供爻名、卦名、点选、铜钱摇卦、电脑摇卦和电脑起卦六种方式；各输入最终统一转换为六个 `DivinationLine`，映射边界在 `HomeModels.kt` 与 `DivinationRequestBuilders.kt`。
- 卦名起卦要求选择本卦上卦和下卦；变卦上下卦可分别留空并沿用本卦对应位置，最终按本卦与变卦逐爻差异生成动爻。
- “电脑摇卦”只在设备本地随机模拟三枚铜钱并按初爻到上爻依次生成，不请求网络；电脑起卦对少阳、少阴、老阳、老阴等概率取值，不模拟三枚铜钱的概率分布。
- 切换起卦方式会清空各方式已有爻值。首页只收集问念和起卦输入，请求组装负责校验时间及六爻，排盘计算不进入 Composable。
- 问念允许为空且不阻止排盘；它参与历史判重，并决定“问念非空”自动保存策略是否触发。
- 完整链路为首页状态 + 已确认时间 + 23 点设置 -> `DivinationRequest` -> `ResultViewModel.showResult` -> 结果页；任一输入不满足领域契约时停留首页并提示。

## 结果展示

- `ResultScreen.kt` 展示问念、现状、断语、神煞、时间四柱及六爻表格；表格数据来自 `DivinationResult`，设置只改变可见信息、缩写、提示和高亮。
- 六爻表格是 Compose 中嵌入的原生 `HorizontalScrollView + TableLayout`，用于统一动态列测量；调整表格架构时需同时核对动态列、字体缩放和横向滚动，不在文档固化列宽或像素。
- 日月冲合、回头作用、旬空及同支/冲/合高亮由 `DivinationPromptHints.kt` 派生，结果主体和这些提示保持职责分离。

## 保存与编辑

- 未命中历史判重时，新结果可手动保存到默认分组，也可按“不保存”、“问念不为空”、“始终保存”策略自动保存到设置分组。
- 只有已保存记录可编辑问念、现状和断语；修改问念会同步更新请求、结果及历史列表标题。
- 历史恢复、判重和兼容约束见 `index.md` 与 `history.md`；派生提示和展示设置仍按当前版本作用于恢复出的结果。
