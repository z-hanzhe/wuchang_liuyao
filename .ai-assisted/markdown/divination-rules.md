# 排盘规则

## 职责与入口

- `domain/divination/HexagramCalculator.kt` 是排盘纯计算入口，`DivinationModels.kt` 定义请求与结果契约，`DivinationPromptHints.kt` 负责日月冲合、回头作用、旬空和地支高亮关系。
- 六十四卦名、八宫、卦宫五行、纳甲、六亲、六神、伏神、神煞、旬空及冲合表固化在领域代码中，运行时不查数据库或外部排盘库；完整表值不在文档复制。

## 输入与输出契约

- 一次排盘必须有六爻、日干、日支和月支。标准爻序及方向转换见 `index.md`。
- `DivinationLine` 的持久化 code 是稳定兼容契约：1 少阳、2 少阴、3 老阳、4 老阴；老阳和老阴为动爻。
- 请求包含问念、起卦方式、日期四柱和六爻；结果包含本卦/变卦信息、卦宫与卦型、六神、六亲、纳甲、伏神、常用神煞、旬空及六行结果。
- 卦名起卦的本卦上卦和下卦必填；变卦对应位置未选择时沿用本卦，同爻保持静爻，阳变阴转换为老阳，阴变阳转换为老阴。
- 存在任一动爻时，变卦是完整六爻结果：六行均保存变卦爻、纳甲和六亲，只有实际动爻行带变化标记；结果展示和历史快照不得缩减为只保留动爻行。
- 提示和点击高亮是从结果派生的领域信息，不参与卦码计算；开关只控制展示，不应改变已算出的排盘结果。

## 稳定业务口径

- 变卦卦宫和卦型按变卦自身计算用于展示，但变卦六亲继续沿用本卦卦宫五行，不按变卦宫重新定六亲。
- 伏神先按本卦所属宫的纯卦生成；结果页再根据设置展示与本卦不同的候选，或仅补本卦缺失的六亲。
- 神煞依赖日干、日支或月支，六神依赖日干，旬空依赖合法日柱；因此干支手选不能缺少最低必填字段。
- 修改世应、认宫、纳甲、六亲、伏神、神煞或旬空规则前，必须核对可靠来源并为边界卦例补充可重复验证，禁止仅凭记忆调整表或推导。
